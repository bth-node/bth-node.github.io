Det här kursmomentet löper över två veckor och är kursens examinerande del. Du visar att du behärskar det du har byggt, skriver en sammanhållen redovisning av hela kursens gång och väljer hur djupt du vill gå beroende på vilket betyg du siktar på.

## Grundkrav — betyg D och E

För ett godkänt betyg ska hela din applikation fungera och obligatoriska issues från kmom04, kmom05, kmom06 skall vara implementerade.

Dessutom skall du implementera följande obligatoriska krav, som var sitt GitHub-issue i ditt repo:

| Issue | Namn            | Vad du gör                                                  |
| ----- | --------------- | ------------------------------------------------------------ |
| 10a   | `search-users`   | Utöka `GET /api/users` med valfri sökning på namn            |
| 10b   | `profile-update` | Lägg till `PATCH /api/me` för att uppdatera namn och/eller avatar |

Beskriv implementationen och dina designbeslut för respektive krav i redovisningstexten.

## Optionella krav — betyg C, B och A

Varje krav du klarar höjer betyget ett steg, upp till betyg A. Kraven är fristående av varandra — det finns ingen ordning du måste göra dem i, och inget krav förutsätter att ett annat är klart. Varje krav listar sina egna, konkreta issue-beroenden. Beskriv vad du gjort och varför i redovisningstexten.

| Krav                       | Issue(s)                                                |
| --------------------------- | -------------------------------------------------------- |
| Terminalklienten             | `10e` (`terminal-client`)                                |
| TUI för sökning och profil   | `10d` (`tui-search-and-profile`), kräver `04e` och `07a` |
| Tester                       | `10c` (`test-coverage`)                                  |

## Redovisning

Se till att följande frågor besvaras i din redovisningstext i `report/kmom10.md`.

1. För varje krav du implementerat (grundkrav och krav 1–3), skriver du ett textstycke om ca 5-10 meningar där du beskriver vad du gjort och hur du tänkt. Poängsättningen tar sin start i din text så se till att skriva väl för att undvika poängavdrag. Använd rubriker så din text blir lätt att läsa.

   **Missar du att skriva/dokumentera din lösning så blir det 0 poäng. Du kan inte komplettera en inlämning för att få högre betyg.**

2. Skriv ett allmänt stycke om hur projektet gick att genomföra. Problem/lösningar/strul/enkelt/svårt/snabbt/lång tid, etc. Var projektet lätt eller svårt? Tog det lång tid? Vad var svårt och vad gick lätt? Var det ett bra och rimligt projekt för denna kursen?

3. Vilken är din TIL för detta kmom?

4. Vilken är din TIL för kursen som helhet?

5. (Valfritt) Avsluta med ett sista stycke med dina tankar om kursen och vad du anser om materialet och handledningen (ca 5-10 meningar). Återkoppla till lärarteamet och förslå eventuella förbättringsförslag till kommande kurstillfällen.

6. (Valfritt) Är du nöjd/missnöjd? Kommer du att rekommendera kursen till dina vänner/kollegor? På en skala 1-10, vilket betyg ger du kursen?

## Inlämning

1. Stäng de GitHub-issues som du har löst klart.
2. Skriv klart din redovisningstext i `report/kmom10.md`.
3. Kör `npm test` för att se att dina tester passerar.
4. (Valfritt) Kör en självkoll: `npm run check -- kmom10` — kontrollerar att redovisningstexten är klar och att alla obligatoriska issues är stängda, samma kontroll som körs automatiskt när du öppnar PR:en nedan.
5. Committa, tagga och pusha:

  ```bash
  git add .
  git commit -m "kmom10 done"
  git tag v10.0.0
  git push origin main --tags
  ```

6. Öppna en pull request från `main` till `bth/submit/kmom10` i ditt repo.

Läraren läser din redovisningstext via `report/kmom10.md` i PR:en och bedömer vilka krav som är uppfyllda.

Behöver du uppdatera din inlämning efteråt? Committa ändringen, tagga om med en ökad patch-version (t.ex. `v10.0.1`) och pusha — PR:en uppdateras automatiskt.
