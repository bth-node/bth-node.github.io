Den här veckan tar du scraping till nästa nivå. Du hittar tabeller dynamiskt utan hårdkodade ID:n, hämtar flera sidor parallellt med `Promise.all` och sparar resultaten till en JSON-fil. <summary>Genomgång, ca 2 timmar</summary>

Genomgången visar begreppen och hur de fungerar — studenterna gör uppgifterna själva. Använd korta isolerade exempel i terminalen, inte studenternas kod.

### Block 1 — Promise.all och parallellitet (60 min)

Visa skillnaden mellan sekventiell och parallell exekvering med ett minimalt scratch-skript. Poängen är att studenten förstår vad `Promise.all` faktiskt gör — inte bara att det "är snabbare".

- Visa att ett `fetch`-anrop returnerar ett Promise direkt — det väntar inte på svar
- Visa sekventiell `await` med `console.time`: tre `await fetch(...)` efter varandra — tid = summan
- Visa `Promise.all`: skapa tre promises med `.map()`, skicka dem parallellt — tid = den långsammaste
- Visa att resultaten kommer i samma ordning som input, oavsett vilket anrop som svarar först
- Visa vad som händer om ett promise i `Promise.all` rejectar — hela anropet misslyckas
- Visa `JSON.stringify(obj, null, 2)` på ett litet objekt i REPL — skillnaden med och utan indentering
- Visa `writeFile` och `readFile` från `node:fs/promises` på en enkel sträng

### Block 2 — Autentisering med tokens (50 min)

Visa auth-flödet med `curl` eller ett litet scratch-skript mot den körande servern. Gör det synligt — visa statuskoderna, visa token-strängen, visa att samma URL ger 401 utan token och 200 med.

- Starta `npm run site-1` och visa att `/intern.html` ger `401` med `curl -i` eller ett fetch-skript utan headers
- Visa ett POST-login-anrop och skriv ut hela JSON-svaret — peka på `token`-fältet
- Dekoda JWT-strängen manuellt på [jwt.io](https://jwt.io) — visa header, payload och att signaturen inte avslöjar lösenordet
- Visa ett fetch-anrop med `Authorization: Bearer <token>` → `200 OK`
- Visa `403` genom att använda personal-token mot `/chef.html`
- Visa `.env`-filen och `process.env.VARIABLE` i REPL med `dotenv` — varför det inte ska checkas in
- 5 min: hur samma token-mönster återkommer i verkliga API:er (GitHub, Stripe, etc.)
