Den här veckan kommer du igång med Node.js-backendutveckling. Du skapar din första Express-server, bygger ett REST API och sätter upp verktyg för kodkvalitet — linting, formattering, CI och automatiserade tester. Veckan lägger grunden för resten av kursen.

## Kom igång

Ditt repo är förberett och finns på GitHub. Klona det till din dator:

```bash
git clone git@github.com:bth-node/backend-<studentakronym>.git
cd backend-<studentakronym>
```

Fortsätt sedan med README.md i repot för att installera beroenden och starta upp miljön.

## Issues

Arbeta igenom issues i ordning. Varje issue är ett steg framåt i applikationen.

Du är välkommen att skriva egna kommentarer i varje issue medan du arbetar — noteringar, frågor eller korta reflektioner om vad du lärde dig. Det hjälper dig att minnas och ger läraren inblick i din process. Stäng ett issue när du anser att det är klart.

| Issue | Namn | Vad du gör |
|---|---|---|
| 01 | `getting-started` | Klona repot, se frontenden med `npx serve` |
| 02 | `dev-environment` | Konfigurera ESLint, Prettier, VS Code-tillägg |
| 02a | `ci` | Sätt upp GitHub Actions — lint på push |
| 03 | `express` | Skapa Express-server, servea frontenden som statiska filer |
| 04 | `rest` | Bygg REST API med HTTP-metoder och statuskoder (in-memory) |
| 04b | `api-doc` | Lägg till `GET /api/doc` — ett självbeskrivande API-endpoint |
| 04c | `logging` | Strukturerad loggning med Pino och pino-pretty |
| 04d | `testing` | Integrationstester med Vitest och supertest, kodtäckning |

## Redovisningstext

Skriv dina svar i `report/kmom04.md` i ditt repo. Skriv ett par meningar om varje fråga — svaret ska visa att du förstår det du gjort, inte bara att du gjort det.

1. Beskriv hur du strukturerade din Express-server. Varför är det en bra idé att dela upp `server.js` (app-konfiguration) och `index.js` (start och livscykel) i separata filer?

2. Vad är REST? Förklara skillnaden mellan `GET`, `POST`, `PATCH` och `DELETE` och ge ett konkret exempel från ditt API på när var och en används.

3. Du lade till linting och automatiska tester i CI. Vad är syftet med GitHub Actions i det här sammanhanget, och vad händer om lintern hittar ett fel?

4. Vad är ett integrationstest och hur skiljer det sig från ett enhetstest? Vad testade du i issue 04d och varför valdes just de sakerna?

5. Vad är din viktigaste insikt (TIL — Today I Learned) från det här kursmomentet?
